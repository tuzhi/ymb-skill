# 项目协作规范

本仓库是银行流水标准化项目。核心目标是把 Excel/CSV/可抽取文本 PDF 流水转换为统一中文字段，并支持整合、余额校验、打标、交付物生成和 testdata 支持矩阵回归。

## 设计入口

银行流水标准化相关任务的完整模块索引、代码入口、设计文档入口和验收入口，以 Obsidian 中的模块索引为导航事实源：

- `流水分析工程/00-入口/流水标准化模块索引.md`

Obsidian vault 根路径以 Codex 全局配置为准；本文件只维护 vault 内相对路径。

`AGENTS.md` 只维护冷启动协议和稳定协作约束；不要在这里判断模块归属，也不要复制完整模块索引、代码模块清单或测试入口清单。

## 固定执行链条

每次处理银行流水标准化任务，都按下面顺序显式执行。

1. **读取模块索引**：先读取 `流水分析工程/00-入口/流水标准化模块索引.md`；不在 `AGENTS.md` 内判断模块归属。
2. **定位设计文档**：按模块索引确定当前模块、设计文档、代码入口和验收入口；若用户同时提到多个模块，先读最靠近失败现象的模块，再读交叉模块。
3. **查看调用链**：用 Codegraph 或本地代码搜索确认入口、调用链、影响面和已有测试；不要只凭文件名或历史印象判断。
4. **执行最小验收**：默认只跑模块索引中对应的最小验收；未经用户明确指令，不跑全量回归或全量 support_matrix。
5. **同步事实源**：若新增模块，更新 `流水分析工程/00-入口/流水标准化模块索引.md`；若新增指纹、样本归属或验收口径，更新对应 Obsidian 设计文档或 `support_matrix.xlsx`。

对用户沟通时，也按这条链条简短说明：“我先读哪个 AGENTS/索引/设计文档，本次落在哪个模块，哪些边界不能碰，最后跑哪个最小验收”。

## 项目规范

- Python 项目元数据以 `pyproject.toml` 为事实源。
- 项目本有venv虚环境
- 共享标准化内核位于 `ymb-standardization-core/`。
- Skill 封装位于 `bank-statement-standardization/`。
- PDF/Excel 输入识别优先放在 shared core 的 reader/router/input 层。
- 大体积开发数据不进入项目源码目录；默认位于仓库同级
  `../ymb-skill-data/{testdata,testoutput,原始流水数据}`。
- 可用 `YMB_STANDARDIZATION_DATA_ROOT` 覆盖外部数据根目录。
- `tools/release/package_skill.py` 为打包脚本。
- 代码注释优先中文说明。
