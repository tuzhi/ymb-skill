# 附件C：建议随 Prompt 提供的附件清单

为了让 prompt 在其他大模型环境中稳定使用，建议每次调用时附带以下材料。

## Prompt 1：流水文件识别与字段映射

建议附件：

- 原始文件，或脱敏后的前 20 至 50 行样本。
- 文件名称、文件类型、疑似银行。
- 每列统计信息，如非空率、日期样式、金额样式、文本样式。
- 已知模板或历史字段映射，如有。
- `附件A_标准化流水字段说明.md`。

## Prompt 2：单客户多流水文件整合与验证

建议附件：

- 同一客户下所有文件的标准化流水。
- 每份文件的来源信息，包括文件名、银行、账户、期间。
- 客户主体信息，包括客户名称、证件号码或统一社会信用代码。
- 已知自有账户清单，如有。
- 解析质量报告或字段映射置信度，如有。
- `附件A_标准化流水字段说明.md`。

## Prompt 3：交易标签梳理与规则沉淀

建议附件：

- 单客户整合后的标准化流水。
- 标签体系。
- 已有关键词规则。
- 已有人审确认规则。
- 历史标签样例，如有。
- `附件A_标准化流水字段说明.md`。
- `附件B_标签体系参考.md`。

## Prompt 4：多客户标准化流水整合与验证

建议附件：

- 客户清单。
- 每个客户一份标准化流水。
- 客户主体信息和关联主体信息。
- 每个客户的解析质量结果。
- 每个客户的标签结果，如有。
- 批量校验规则或机构内部数据质量标准。
- `附件A_标准化流水字段说明.md`。

## 脱敏建议

在交给外部模型前，建议脱敏：

- 本方账户和对手账户，只保留后四位。
- 身份证号、手机号、统一社会信用代码。
- 个人姓名可用甲、乙、丙或客户编号替代。
- 大额交易可保留金额区间，但如果需要余额校验，应保留原始金额。

## 输出检查建议

模型输出后，建议人工或程序检查：

- 是否为合法 JSON。
- 是否只使用中文流水字段名。
- 是否保留来源文件名和来源行号。
- 是否存在自动删除交易、自动修正交易、自动合并客户等高风险动作。
- 是否把低置信事项放入人工复核。
