# 附件A：标准化流水字段说明

以下字段用于所有 prompt。实际业务中可以增加字段，但核心字段名称建议保持一致。

| 字段名称 | 是否关键 | 说明 |
| --- | --- | --- |
| 客户编号 | 是，多客户场景 | 批量客户分析时的客户唯一标识。 |
| 客户名称 | 是，多客户场景 | 客户主体名称。 |
| 客户证件号码 | 否 | 统一社会信用代码、身份证号或其他主体识别号。 |
| 客户类型 | 否 | 对公、个人、个体工商户或未知。 |
| 交易唯一编号 | 是 | 单笔交易的唯一标识，**取自交易内容指纹**：本方名称/账户 + 交易时间 + 对手名称/账户 + 收入金额 + 支出金额 + 账户余额（不含来源文件/行号）。同一笔交易在不同文件（PDF 与 Excel 同源、整份文件重复提交）会得到**相同编号**，作为跨文件去重依据；同一文件内偶发的真实重复笔追加 `-2/-3` 序号保证唯一。 |
| 交易时间 | 是（必填，不可空缺） | 交易发生时间或记账时间。若原始文件把日期与时间**拆成两列**（如 `入账日期` + `入账时间`、`交易日期` + `交易时间`），须合并为完整时间戳 `YYYY-MM-DD HH:MM:SS`；仅有日期列时补 `00:00:00`。列缺失或某些行解析为空，都应进入人工复核。 |
| 本方名称 | 建议必填 | 流水所属户名。 |
| 本方账户 | 是 | 流水所属账号、卡号或账户编号。 |
| 开户行 | 建议必填 | 本方账户的开户银行（规范名）。可由文件名、抬头/表头文本推断；无法确认时留空并进人工复核。 |
| 账户类型 | 建议必填 | 对公、个人或未知。区分对公对私、混合主体批量分析时必备。 |
| 对手名称 | 建议必填 | 交易对方名称。 |
| 对手账户 | 否 | 交易对方账号。 |
| 收入金额 | 是，与支出金额二选一 | 入账金额、贷方金额、收入。 |
| 支出金额 | 是，与收入金额二选一 | 出账金额、借方金额、支出。 |
| 交易金额 | 是 | **统一口径：交易金额 = 收入金额（空当 0）− 支出金额（空当 0）**，带符号（流入为正、流出为负）。若原始文件只有单列金额，先结合收支方向拆出收入/支出，再据此回填。 |
| 账户余额 | 建议必填 | 交易后余额，用于余额连续性校验。 |
| 银行备注 | 否 | 银行侧摘要、用途、交易摘要。 |
| 账户方附言 | 否 | 客户填写的附言、留言、备注。 |
| 交易渠道 | 否 | 网银、柜面、转账、POS、支付平台等。 |
| 一级标签 | 否 | 交易标签的一级分类。 |
| 二级标签 | 否 | 交易标签的二级分类。 |
| 三级标签 | 否 | 交易标签的明细分类。 |
| 来源文件名 | 是 | 原始文件名称。 |
| 来源行号 | 是 | 原始文件中的行号、页码加行号或解析定位。 |

## 金额方向约定

- 收入金额大于 0 且支出金额为空或为 0，表示资金流入。
- 支出金额大于 0 且收入金额为空或为 0，表示资金流出。
- 同一笔交易原则上不应同时存在收入金额和支出金额均大于 0。
- 交易金额统一回填为「收入金额（空当 0）− 支出金额（空当 0）」的带符号净额：流入为正、流出为负；收入与支出均为空（本行未解析出金额）时交易金额留空，不臆造 0。后续分析的金额方向仍以收入金额/支出金额为准，交易金额作为带符号的便捷列。

## 行序与余额连续性约定

- 余额是对账真值。银行导出排序各异：整体倒序（最新在上）、按日期升序但日内倒序、同秒/同毫秒多笔、内部记账序与时间戳不一致。**不要简单「按交易时间排序」**，否则会打乱同时刻多笔、搅乱倒序文件，产生大量伪余额断点。
- 应把每个文件（及账户跨文件合并去重后）的行序**重排成「账户余额 = 上一笔余额 + 收入 − 支出」连续的正序**：在「原序 / 整体翻转 / 按日期升序 / 按余额链重建」等候选中，选余额断点最少者；同时刻多笔保留其相对顺序、来源行号不变可追溯。
- 重排后仍存在的余额断点多在**跨月/跨文件边界**（缺月、对账单不连续等真实问题），只标记并进入人工复核，不自动修正。

## 证据追溯约定

所有重要结论都应能追溯到：

- 客户编号
- 客户名称
- 本方账户
- 交易唯一编号
- 来源文件名
- 来源行号
