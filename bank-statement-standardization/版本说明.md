## v1.1（2026-06-02）

相对 **v1.0（初始版）** 的全部改动，按主题归类。涉及脚本主要在 `scripts/`，口径文档在 `references/` 与 `SKILL.md`。

### 一、字段口径变化（影响所有下游）

- **新增列 `开户行`**：由文件名 / 抬头 / 表头中的银行名推断为规范行名（工农中建交、招行/浦发/中信…
  及三湘/长沙/上饶/江西/邮储/农商/农信等）；无法确认留空并进人工复核。
- **新增列 `账户类型`**：对公 / 个人 / 未知，随行数据贯穿标准化→整合→打标→底表/交付物
  （v1.0 只把账户类型放在报告里、丢在行数据外，混合对公对私批量时无法区分）。
- **`交易金额` 改为统一回填**：`交易金额 = 收入金额(空当0) − 支出金额(空当0)`，带符号（流入正、流出负）；
  收支皆空才留空。v1.0 仅在「单列带符号 / 方向+金额」结构下填，分列结构留空、且方向+金额时符号可能为正。
- **`交易唯一编号` 改为内容指纹**：`md5(本方名称/账户 + 交易时间 + 对手名称/账户 + 收入 + 支出 + 余额)`，
  不再含来源文件/行号；同一笔交易跨文件得到相同编号，作为去重依据；同文件内真实重复笔加 `-2/-3` 后缀。
- **标准化明细列序**：`交易唯一编号 交易时间 本方名称 本方账户 开户行 账户类型 对手名称 对手账户
  收入金额 支出金额 交易金额 账户余额 银行备注 账户方附言 交易渠道 来源文件名 来源行号`。
- **交付物主表列序**：`银行备注 / 账户方附言` 移到 **`虚拟账户余额` 之后**（金额→余额→备注/附言→标签→渠道/来源）。

> 兼容性：旧版 `*__standardized.csv`（无开户行/账户类型列）仍可被 `integrate.py` 读取，缺列自动补空。

### 二、多文件拼接去重（修复重复流水）

- `integrate.py` 新增 **跨文件去重** `dedup_cross_file`：交易唯一编号（内容指纹）完全一致即视为同一笔交易的
  跨文件再导入（PDF 与 Excel 同源、整份文件重复提交），**折叠为一笔**，保留优先级：结构化表格 > PDF、
  字段更全、来源行号更小；移除明细写入报告 `跨文件去重`，并在概览给出 `原始交易数 / 跨文件去重笔数`。
- 仅折叠「完全一致」者；部分字段一致的疑似重复仍**只标记、不删除**（红线不变）。

### 三、识别更多表头格式 + 交易时间必填

- 同义词词典新增：`入账日期→交易日期`、`入账时间→交易时间`、`对方单位→对手名称`、
  `转入金额→收入金额`、`转出金额→支出金额`、`本方账号→本方账户`（修复 `转入/转出金额` 误命中「交易金额」）。
- **拆列日期+时间**（如 `入账日期`+`入账时间`）自动合并为完整时间戳；移除过宽的裸 `日期`/`时间` 词
  （避免把 `起息日期`/`到期日期`/`打印时间` 误当交易时间）。
- 修复 **紧凑时间戳** `YYYYMMDDHHMMSS[毫秒/流水号]`（如农行「交易时间戳」`20230201195010370199`）的解析
  （v1.0 会把日期段误当时分秒、精度被毁）。
- **交易时间作为必填字段**：列缺失、或部分行解析为空，都升级为人工复核项。

### 四、行序按余额连续性还原（消除伪余额断点）★ 核心修复

- v1.0 在余额校验/输出时**按交易时间排序**，导致：① 同秒/同日多笔被打乱；② 倒序对账单被搅乱；
  产生大量伪余额断点。
- 改为**以余额为对账真值**：`standardize.best_continuity_order` 在「原序 / 整体翻转 / 按日期升序·日内原序 /
  按日期升序·日内翻转 / 余额链重建」中选**余额断点最少**的行序。
  - **余额链重建**：每行紧跟在「余额 = 本行余额 − 本行净额」的那一行之后，专治同秒多笔与「内部记账序≠时间戳」。
- 两层应用：标准化按文件整理；`integrate.order_accounts_for_continuity` 按账户对**跨文件合并、去重后**的行重排。
- 下游 `portfolio_balance.py` / `multi_customer.py` **保留整合后的行序**（用行序 `__seq`），不再按时间重排。
- 新增 **汇总/页脚行过滤**：交易时间无有效日期且无对手/摘要/附言（如农行「总收入笔数/总支出金额」及其数值行）丢弃。
- 实测（丰城利华 80 文件 / 32,384 笔）：文件内余额断点 **由数百降至 0**，仅余跨月/跨文件边界的真实缺口。

### 五、自动排除杂入的非流水文件

- 新增筛选层（`standardize.classify_ext / screen_files / NotABankStatement`）：
  - 图片 / 扫描件 / Word / PPT / 压缩包等格式 → 跳过并说明原因；
  - **图片型/扫描件 PDF**（抽不到文本）→ 跳过，提示先 OCR；
  - **非流水表格**（如混入的发票、名册：缺「金额/余额」或缺「时间/余额」定位列）→ 跳过；
  - 无关文件（.DS_Store 等）静默忽略；流水线自身产物（`*__打标流水.csv` 等）不被当原始数据重复摄入。
- 被跳过的文件**全部留痕**：`run_pipeline` 打印清单；交付物封面有「已跳过文件数」、「人工复核事项」表逐条列出。

### 六、交付物可复用已有产物（`--reuse`）

- `package_deliverable.py` 新增 `--reuse 产物目录或 *__打标流水.csv/*__整合流水.csv`：直接用 `run_pipeline`
  已有的整合/打标产物组装交付物，**跳过重复跑标准化/整合/打标**；与 `--folder`/`--subject` 共用同一尾段
  （`_finalize`），交付物口径完全一致。避免「为省算力而手工拼表」导致列序/虚拟余额/去重等保证丢失。

### 七、余额断点诊断（识别「解析不全」≠「排序问题」）

- 余额校验新增 `断点率` 与 `疑似解析不全` 字段：断点率 > 30% 时直接判为「极可能解析不全/漏行/只读了文件
  部分行（大表被截断或抽样），请核对原始文件总行数并用脚本完整重跑」，而非「对账单排序问题」。
- `SKILL.md` 增加强约束：**大文件必须用脚本解析，切勿让模型逐行读原始表再转写**（上下文截断会只读到一小部分行，
  断点率畸高即此症状）。
