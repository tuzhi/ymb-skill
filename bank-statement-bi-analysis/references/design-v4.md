# 经营流水 BI 分析报告 · V4.0 设计（对标见知现金流尽调系统）

> V4.0 = **V3.0 全部分析引擎** + **见知（Xencio）现金流尽调系统的呈现风格与账户级明细**。
> 对标素材：见知系统五个网页（尽调报告/流水明细/分类规则/主体与账户/文件记录）与其导出的
> 《专业版-现金流分析报告》.xlsx（康业国际样例，单表 305 行纵排）。
> 输出仍为**纯 Excel 渲染**（openpyxl，原生图表），不引入 HTML。

## 二、见知设计风格 → Excel 落地规范（V4 样式系统）

从见知导出 xlsx 逆向的样式要素，V4 全部沿用：

1. **单表纵排 + 章节编号体系**：`一/二/三…` 大章、`x.y` 小节、`x.y.z` 子节；
   A 列为窄编号列（宽 6），章号与表内序号（1,2,3…）都放 A 列，内容从 B 列起。
2. **字体**：全局微软雅黑；正文 11pt（见知原版 12pt，考虑账户×月矩阵列密度略缩一号）；
   报告标题 22pt 加粗 `#1F4E78`；大章 16pt 加粗 `#1F4E78`；小节 13pt 加粗 `#2F75B5`；子节 11pt 加粗 `#2F75B5`。
3. **语义配色**：表头**流入/中性 = 浅蓝填充 `#99CCFF`**、**流出 = 浅红填充 `#FF7E79`**；
   警示值**橙色字体 `#FFC000`**（如「3差异较大」「一般」）；**无边框**（不画表格线，靠填充与留白分区）。
4. **KPI 卡**：标签行（填充色+加粗）与数值行上下相邻，2–4 个一组；流出类 KPI 用红卡。
5. **明细表**：A 列序号、末行「总计」加粗；月度矩阵统一 12 列月份 + 合计/均值列；
   数字右对齐 `#,##0.00`，占比 `0.00%`；金额单位=元（报告头声明）。
6. **口径脚注**：表下用灰斜体注明「已剔除以下分类的流水: …」等口径说明。
7. 保留我们自己的三个视觉约定（见知没有但审批需要）：看板判断绿/黄/红底、
   假设单元格黄底、可修改推演输入蓝字。
8. **长文本排版**：说明/证据/备注类长文本列横向合并单元格（`table(spans={逻辑列: 合并列数})`），
   口径脚注与段落文本合并 B 起若干列（`mtext`/`foot`）；所有换行单元格按内容估算行高
   （CJK 计 2 个宽度单位，Excel 对合并单元格不会自动撑高，必须显式设 height）；
   窄列长表头统一换行+撑高（`hdr_row`），不再靠溢出/截断。

## 三、V4.0 报告结构（6 sheet，编号贯穿）

> **章节排序原则**：事实类数据在前（速览、余额/借贷/收支/对手方等指标明细），
> 数据分析/校验类在后（数据验证、生意模式与审批要件）。主用户是客户经理与风险审批官，
> 先看经营事实再看分析判断；量化策略经理（次要用户）的机器可读指标集在 Sheet5「风险指标」；末表 Sheet6 为标准化流水明细（手工分析用）。

### Sheet1 分析报告
- **报告头**：标题、金额单位/货币单位、客户/关联主体/流水区间/策略版本、多币种提示
- **数据处理概况（按主体）**：原始文件数/账户数/标准化笔数/流水期间/打标命中笔数与命中率（规则库命中口径），
  展示标准化与标签化处理成功情况；明细见 Sheet6
- **一 核心速览**
  - 1.1 核心统计：主体/账户/数据时长卡 → 日均余额/借贷流入/偿还借贷卡 → 有效流入/有效流出卡
    → TOP5 有效流入方 & 流出方对照表（B/C 列流入蓝、D/E 列流出红）
  - 1.2 风险提示：综合数据质量、余额断点账户数、质量风险账户数、关联方、疑似关联外部方、
    需关注对手方、个人敏感支出笔数、隐藏账户信号组数（异常值橙字）
- **二 指标明细**（事实层）
  - 2.1 余额分析：2.1.1 日均余额（账户×月+均值+总计）；2.1.2 月末余额（同结构）
  - 2.2 借贷分析：2.2.1 借贷趋势（借贷流入/偿还借贷/净额 ×月）；2.2.2 借贷方明细（类型：银行/非银/民间/其他）
  - 2.3 收支分析-趋势：2.3.1 流入（账户×月，蓝头）；2.3.2 流出（账户×月，红头）
  - 2.4 收支分析-构成：2.4.1 流入（二级标签×月+占比+均值）；2.4.2 流出；含剔除口径脚注
  - 2.5 对手方分析：2.5.1 前10大流入方（类型/构成%/×月）；2.5.2 前10大流出方；
    2.5.3 流入/流出重合方（重合金额/重合比）；2.5.4 对手结构指标（HHI/留存/对私/白名单，V3）
  - 2.6 关联方交易：2.6.1 集团成员间互转（成员对清单）；2.6.2 疑似关联外部方（对倒判定，V3）；
    2.6.3 工商关联方（法人/股东/对外投资，待外部数据）
  - 2.7 需关注对手方：风险点（个人大额往来/大额整数交易/司法/投机赌博/民间借贷）+流入/流出/差额
  - 2.8 个人敏感支出：2.8.1 夜间大额时段分布（22:00–06:00 小时桶×对私流出金额/笔数）
- **三 数据验证**（分析层）
  - 3.1 数据完整性校验：按主体分块，账户级（账号/开户行/币种/数据时间范围/时长/余额断点/对手名称/交易信息）
  - 3.2 数据质量验证：账户级评级表（结息记录/字段完整度/评级/详情）→ 四维质量评分（V3）
    → 真实性校验清单（V3：余额勾稽/结息复算+明细/Benford/整数占比/快进快出/夜间）
  - 3.3 未提交账户：账号级清单（成员名下、未在提交账户集内的对手账号；流入=流向该账号金额）
    + V3 规则型缺失账户反推（月供无放款/担保费无贷款/薪酬失配）
  - 3.4 主体名称核验：个人户主建议企业主体（待工商数据/人工确认）
- **四 生意模式与审批要件**（V3 模块平移）
  - 4.1 生意模式（证据自动汇集+定性待填）
  - 4.2 审批要件指标看板（红/黄/绿）
  - 4.3 重大风险行为信号（疑似度+证据链）
  - 4.4 行业专家评分（得分待标定）
  - 4.5 交叉验证矩阵（流水列已填）

## 四、V4 新增口径

- **有效流入/有效流出**（对标见知「有效」概念，口径以我们标签体系定义并在报告中声明）：
  剔除 ①内部互转 ②筹资类全部（负债/银行借款/民间借贷/消费金融/信用卡/吸收投资/其他筹资）
  ③经营类·票据及贸易融资 ④投资类·存款结息 ⑤经营类·退款交易 后的流入/流出。
  即「真实对外经营+投资往来」口径；TOP5 有效流入/流出方在此口径上统计。
- **借贷流入** = 筹资类收入 + 票据及贸易融资收入 + 金融机构大额放款修正（≥50万且对手为金融机构，
  即使误标）；**偿还借贷** = 筹资类支出 + 偿还票据及贸易融资。
- **借贷方类型**：对手含「银行」→银行；含 金租/租赁/保理/小额贷款/消费金融/信托/担保/典当→非银；
  个人姓名（nature=个人）→民间；其余→其他。
- **未提交账户**：内部互转行中 `对手账户` 非空、且不在本次提交的 `本方账户` 集合内的账号，
  按（成员名, 账号）聚合；「流入金额」= 已提交账户流向该账号的金额（即我们的支出），
  「流出金额」= 从该账号流入我们的金额，差额=流入−流出。无 `对手账户` 列时降级为
  「成员名下未知账号（按对手名称聚合）」并注明。
- **需关注对手方**（外部对手，按命中规则打风险点标签，可多标）：
  个人大额往来（个人对手且双边合计≥50万）；大额整数交易（存在单笔≥100万且为万元整数）；
  司法对手（法院/执行局/仲裁）；金融投机/赌博对手；民间借贷对手。按合计金额降序，TOP20。
- **个人敏感支出·夜间大额**：有时点、22:00–06:00、对私（个人对手）流出，按小时桶
  （22~23、23~0、…、5~6）列金额与笔数。
- **账户级数据质量评级**：优秀=有结息记录且对手/摘要非空率≥80%且无断点；
  良好=非空率≥60%且无断点；一般=非空率<60% 或 有断点；数据不足=该账户笔数<30 或 月数<3。
  评级仅是数据可用性分级，不是风险结论。

## 五、实现说明

- 脚本：`scripts/build_bi_report_v4.py`。复用 V3 的输入解析与 `analyze()` 全部分析引擎
  （`from build_bi_report_v3 import …`），叠加 `analyze_v4()` 计算本文第四节新增口径，
  再用 V4 样式系统重写 `build_workbook`。V3/V1 脚本保留为兼容入口。
- 账户×月矩阵的「日均余额」按账户日末余额前向填充后按月求均值（与见知口径一致）；
  无余额列的账户显示为空并在 3.2 评级降级。
- 产出后仍需走 SKILL.md 的三步：recalc 重算、补写【待填】定性单元格、口头汇报核心结论。
