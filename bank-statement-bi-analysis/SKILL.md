# 经营流水 BI 分析报告（Bank Statement BI Analysis）

把 **已标准化的经营流水** 变成一份 **图表化、可审批** 的 Excel 分析报告。本技能是
`bank-statement-standardization` 的**下游**：先标准化拿到可信底表，再在此呈现审批分析要件。

## 串行关系（务必先标准化）

```
原始流水 ──[bank-statement-standardization]──> 标准化/整合/打标产物 ──[本技能]──> BI 分析报告.xlsx
```

- 本技能**不解析原始银行流水、不做字段映射、不做余额校验**——那是上游技能的职责。
- 若用户直接甩来原始流水文件让你「做分析报告」，**先调用 `bank-statement-standardization`** 产出标准化产物，
  再用本技能消费。两步可连成一条流水线。

## 快速生产路径（默认且必须使用）

拿到标准化产物（单文件或文件夹）后，直接执行一次：

```bash
python scripts/build_bi_report.py --input "<标准化产物文件或文件夹>" --client "客户名"
```

- 输入支持：标准化交付物 `.xlsx`（自动定位「标准化流水主表/主表/流水」工作表）、
  `*__打标流水.csv`、`*__整合流水.csv`、或任意含标准字段的 CSV；传**文件夹**时自动挑选其中的标准化产物。
- 多个经营主体时**逐主体各出一份报告**（`--client` 为授信归档名，仅用于命名）。
- `--out-dir` 指定输出目录，默认落在输入同级。

## 核心红线

- **绝不按交易时间重排明细。** 标准化产物的行序已按「账户余额连续性」还原（见上游技能红线），
  本技能沿用该行序计算月末余额、余额波动；月度/对手类聚合按月份或对手 key 分组，与行序无关。
- **只读不改。** 本技能只消费标准字段、生成新报告，不回写、不修改标准化产物。
- **阈值是参考，不是结论。** 「审批要件指标看板」的阈值为初筛参考口径（授信方可调，集中在
  `scripts/build_bi_report.py` 顶部 `THRESHOLDS`），红/黄/绿判断**不构成授信决策**，仅供审批人快速定位关注点。
  本技能**不做评分卡、不测额度**（避免臆造未标定模型）。
- **缺数据如实标注**，例如流水不足 24 个月时「流入增长率」显示「数据不足」，不臆造增长率。

## 报告结构（参考发票分析报告模板的两模块布局）

输出 `.xlsx` 含 5 个工作表：

1. **分析报告**（主表）
   - 抬头：客户名称 / 经营主体 / 流水区间 / 账户数 / 报告日期 / 分析策略版本。
   - **模块一 · 经营流水观察**
     - PART1 流水整体概况：采集时长、活跃月数、交易笔数、总/净流入、收支比、日均/最低/最高余额、负余额次数。
     - PART2 收支结构：按二级用途的收入/支出金额与占比（并排）。
   - **模块二 · 审批要件指标看板**：业务规模、收支匹配、稳定性（月流入CV）、连续性（零流入月/最长连续零月）、
     成长性（近12月vs远12月流入）、集中度（TOP1/TOP5对手占比）、现金依赖、往来款占比、余额健康、
     **夜间交易（21:00–06:00 笔数/金额占比，分母取有时点交易并标注时点覆盖率）**——
     每行含口径、参考阈值、企业实际、红黄绿判断。
2. **月度时序表**：月份 × 流入/流出/净流入/笔数/月末余额/月均余额/月最低余额（图表数据源）。
3. **收支结构**：收入、支出各按二级用途的金额表（饼图数据源）。
4. **交易对手**：十大流入对手（上游/客户）、十大流出对手（下游/供应商）、净上游、净下游、
   双向往来对手（同时有收有支，关注资金空转/互转）。
5. **可视化看板**：6 张 **Excel 原生图表**，**单列纵向排布、自上而下下拉查看**，每图放大以免标签拥挤——
   月度流入/流出柱图+净流入折线（组合）、余额波动折线（月末/月最低）、收入用途饼图、支出用途饼图
   （均放大、图例靠右、切片取金额前8+「其他」、标签仅显示百分比并 bestFit 摆放，避免内部文字挤叠）、
   十大流入对手条形图、十大流出对手条形图。图表引用前述数据表，打开即为可交互的原生图表。

## 消费的标准字段

与上游交付物对齐（缺列自动降级）：`交易时间 / 本方账户 / 账户类型 / 本方名称 / 对手名称 /
收入金额 / 支出金额 / 交易金额 / 账户余额 / 收支方向 / 一级标签 / 二级标签 / 三级标签 /
客户名称 / 主体名称`。金额方向以 `收入金额/支出金额` 为准，缺失时回退到带符号的 `交易金额`。

## 依赖

- Python 3，`openpyxl`（生成 .xlsx 与原生图表）。依赖由 `pyproject.toml` 管理，首次使用在本目录执行 `python -m pip install -e .`。

更多分析口径与方法论见 `references/methodology.md`。
