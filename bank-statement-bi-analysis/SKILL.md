# 经营流水 BI 分析报告 V4.0（Bank Statement BI Analysis）

把 **已标准化的经营流水** 变成一份 **图表化、可审批** 的 Excel 分析报告。本技能是
`bank-statement-standardization` 的**下游**：先标准化拿到可信底表，再在此呈现审批分析要件。
V4.0 对标见知（Xencio）现金流尽调系统的报告形态：单表纵排、章节编号（一/x.y/x.y.z）、
流入蓝头/流出红头语义配色、账户级明细矩阵（设计对标与差距清单见 `references/design-v4.md`）。

## 串行关系（务必先标准化）

```
原始流水 ──[bank-statement-standardization]──> 标准化/整合/打标产物 ──[本技能]──> V4.0 分析报告.xlsx
```

- 本技能**不解析原始银行流水、不做字段映射、不做余额校验**——那是上游技能的职责。
- 若用户直接甩来原始流水文件让你「做分析报告」，**先调用 `bank-statement-standardization`** 产出标准化产物，
  再用本技能消费。两步可连成一条流水线。

## 快速生产路径（默认使用 V4 脚本）

```bash
python scripts/build_bi_report_v4.py --input "<标准化产物文件或文件夹>" --client "客户名" \
  [--out-dir DIR] [--whitelist wl.json] [--new-loan 2000000,0.08,12] [--loans 借据表.csv]
```

- 输入支持：标准化交付物 `.xlsx`（自动定位「整合打标流水/标准化流水主表/主表/流水」工作表；若含
  「组合日余额」「余额校验」工作表则直接采用，结息复算与断点统计更精确）、`*__打标流水.csv`、
  `*__整合流水.csv`；传**文件夹**时自动挑选其中的标准化产物。账号列一律按字符串读入（防浮点丢精度）。
- **分析口径＝「全部关联主体合并」**：对手命中集团任一成员（主体名称/本方名称）即判为**内部互转**；
  报告同时给「总口径(含互转)」「净对外口径」与「有效口径」（再剔筹资/票据/结息/退款）三套数。
- `--whitelist`：核心企业白名单 JSON（`{"公司名": ["L1", 1.0], ...}`，建议 L1×1.0/L2×0.8/L3×0.6）；
  不传则该指标按 0 计（报告中注明未配置）。
- `--new-loan`：现金推演的拟授信情景（本金,年利率,期数），默认 200 万/8%/12 期；推演内所有假设为蓝色可改单元格。
- `--loans`：借据表（csv/xlsx），启用风险指标中的借据类；不传则这些指标降级为 -9998。
- V3 脚本 `scripts/build_bi_report_v3.py`（V4 复用其分析引擎）与 V1 `scripts/build_bi_report.py` 保留为兼容入口。
- 风险指标层由 `scripts/generate_vars.py` 的 `compute_spec_metrics` 加工，口径与勘误见
  `references/metrics-processing-spec-v1.md`。

## 脚本产出后 Claude 必须做的三件事

1. **重算公式**：用 xlsx 技能的 `recalc.py` 重算并确认零错误（偿付 Schedule、现金推演、现金流量表均为活公式）。
2. **补写定性单元格**：报告中所有标记 `【待填：定性结论…】` 的单元格——3.4 主体名称核验、
   4.1 生意模式的行业/品类/盈利逻辑/核心风险判断、4.4 行业评分卡的行业维度得分。脚本已把证据自动汇集在
   相邻单元格，Claude 基于证据用 openpyxl 补写结论后再保存一次。评分卡五张分型卡的维度与权重见
   `references/design-v3.md` 模块七。
3. **口头汇报核心结论**：数据质量分与短板、未提交账户/隐藏账户信号、识别债务与月债务服务、
   推演缺口（所需增量融资），并明确哪些结论受账户覆盖与标签质量限制、需要补什么外部数据（征信/发票/工商）。

## V4.0 报告结构（6 sheet，见知风格编号纵排，单表下拉通读）

章节排序原则：**事实类数据在前、分析判断类在后**——主用户是客户经理与风险审批官，先看经营事实
（速览、余额/借贷/收支/对手方明细）再看分析（数据验证、审批要件）；量化策略经理（次要用户）的
机器可读指标集在「风险指标」表；末表「标准化流水明细」供手工筛选分析。

1. **分析报告**：报告头（金额/货币单位、多币种提示）→ **数据处理概况（按主体）**（原始文件数/账户数/标准化笔数/流水期间/打标命中率，标准化与标签化成功情况一目了然）→ **一 核心速览**（1.1 核心统计：主体/账户/时长、
   日均余额、借贷流入/偿还借贷、银行/非银/民间借贷方计数、有效流入/流出 + TOP5 有效流入/流出方；
   1.2 风险提示：质量分、余额断点账户、质量风险账户、未提交账户、关联方、疑似关联外部方、需关注对手方、
   夜间敏感支出；**1.3 年销售额估算（三档口径）**：在有效流入上逐层剔除 补贴退税→对倒过账重合→个人往来拆借，
   得下限/中值/上限三档（嵌套关系）+ 年化 + 剔除项对手明细；下限受打标覆盖率影响，脚本会给敏感性提示）→
   **二 指标明细**（2.1 日均/月末余额账户×月矩阵 + **2.1.3 余额峰值 TOP10 与成因归因**[峰值当日最大单笔流入、
   占峰值%、申贷前90天标记 → 识别冲量]；2.2 借贷趋势 + 借贷方明细
   [银行/非银/民间分型]；2.3 收支趋势账户×月；2.4 收支构成二级标签×月；2.5 前10大流入/流出方×月
   [对方类型+构成%] + 重合方 + 结构指标[HHI/留存/对私/白名单]；2.6 关联方交易[成员互转/疑似关联外部方/
   工商关联占位]；2.7 需关注对手方[风险点+流入流出差额]；2.8 个人敏感支出夜间时段分布；
   **2.9 淡旺季（季节性）分析**[月度季节指数时序 + 自然月跨年合并 + 旺淡月数/最长连续淡季/旺淡季月均净CF]）→
   **三 数据验证**（3.1 主体×账户完整性表；3.2 账户级质量评级 + 四维评分 + 真实性校验
   [余额勾稽/结息复算/Benford/整数/快进快出/夜间]；3.3 未提交账户账号级清单 + 规则型缺失账户反推；
   3.4 主体名称核验）→ **四 生意模式与审批要件**（4.1 生意模式证据+待填；4.2 审批要件看板红黄绿；
   4.3 重大风险行为信号疑似度+证据链；4.4 行业评分卡；4.5 交叉验证矩阵）。
2. **负债与现金流**（五/六）：5.1 债务清单（放款+月供反推 APR；只见月供→隐藏账户债务；民间借贷净敞口→
   气球尾款）→ 5.2 组合 KPI（总本金/WAIR/月债务服务/气球）→ 5.3 未来 12 个月偿付 Schedule →
   6.1 历史月度经营净 CF 与 DSCR → 6.2 未来 12 个月三情景现金推演（触底次数、最低现金、**所需增量融资**、
   DSCR<1.2 月份数）→ 6.3 流水折算现金流量表（会小企03 口径）。
3. **数据明细**（七）：7.1 月度时序表（含借贷流入/偿还借贷列）→ 7.2 TOP12 对手×月矩阵 →
   **7.3 单笔极值卡**（账户×收支方向×经营性/全口径四象限；两者差距大→最大额资金动作非经营行为）→
   7.4 大额交易明细（≥50 万）→ 7.5 疑点交易清单。
4. **可视化看板**：9 张 Excel 原生图表纵排——月度收支组合图、余额三线、经营vs融资vs往来三线、
   **借贷趋势组合图**、收支结构饼×2、十大对手条形×2、现金推演三情景折线。
5. **风险指标**：机器可读指标集（CLN→AF→MK→LS 分段）。哨兵值（-9999/-9986/-9998/-9997）黄色标注，
   入模前须缺失化处理，不得当数值统计。
6. **标准化流水明细**：标准化交付物「整合打标流水」的只读副本（全列+内部互转标记，冻结表头+自动筛选），
   供手工筛选分析，无需再翻看 bank-statement-standardization 的输出。

## 核心红线（沿用并扩展 V1/V3）

- **绝不按交易时间重排明细。** 行序沿用上游「账户余额连续性」还原结果；聚合按月份/对手 key，与行序无关。
- **只读不改。** 只消费标准字段、生成新报告，不回写、不修改标准化产物。
- **阈值是参考，不是结论。** 看板红/黄/绿不构成授信决策；`THRESHOLDS` 集中在 V3 脚本顶部可调。
- **机器不下最终定性。** 风险信号只输出「疑似度+证据链」；负债期限/到期日等假设一律黄色标注并注明反推口径；
  账户质量评级只是数据可用性分级；行业评分卡得分留待人工/Claude 标定。
- **缺数据如实标注。** 无日余额表→余额指标降级近似并注明；无对手账户列→未提交账户降级为规则反推；
  无结息、无白名单、无外部数据均如实显示；多币种未折算时明确提示。
- **数据质量分是前提分。** 未提交账户+隐藏账户信号≥2 组时，全报告收入/负债结论按「已见账户口径」表述，
  先补件再审批。
- **销售额是区间，不是点值。** 1.3 只给下限/中值/上限三档且必须给剔除明细；下限含「仅因未打标而被剔除」的部分，
  应读作「可确证的销售底线」而非真实销售额。任何单一数字对外表述前，须经发票/税务/台账交叉核定。
- **季节性先过覆盖度关。** 2.9 定性前必须剔除「边月」与「在测账户数 < 全期最大」的月份——账户是后期才开户或
  早期流水未提交时，低流水月是数据缺口而非淡季。覆盖不全的月份只列数、不参与旺淡定性。

## 消费的标准字段

与上游交付物对齐（缺列自动降级）：`交易时间 / 本方账户 / 开户行 / 账户类型 / 币种 / 本方名称 / 对手名称 /
对手账户 / 收入金额 / 支出金额 / 交易金额 / 账户余额 / 收支方向 / 一级标签 / 二级标签 / 三级标签 /
客户名称 / 主体名称 / 银行备注 / 账户方附言`。
金额方向以 `收入金额/支出金额` 为准，缺失时回退到带符号的 `交易金额`；
`对手账户` 用于未提交账户账号级检测，缺失时降级并注明。
