# jx-soe-credit-review · 江西省内国企授信审查技能

把业务团队交来的《授信客户尽职调查报告》，审成一份可直接上会的《审查报告》。

## 装什么

```
jx-soe-credit-review/
├── SKILL.md                      主流程（六阶段 + 反套路化硬约束）
├── references/
│   ├── 01-准入与红线清单.md       8 条硬红线 + 4 条软红线（江西口径）
│   ├── 02-点检项全表.md           A–F 六大类 55 条点检项
│   ├── 03-额度测算方法.md         营运资金缺口法 / 订单模式 / 三个调节旋钮
│   ├── 04-勾稽校验规则.md         担保能力口径陷阱 + K01–K10 财务勾稽
│   ├── 05-review-json数据契约.md  脚本输入格式
│   ├── 06-交付前自检表.md         8 组自检，不过不许交
│   ├── 07-穿透抽查池.md           5 池 27 项穿透抽查（反套路化）
│   └── 08-审查报告范文.md         八段式骨架 + 措辞口径 + 禁用空话表
├── scripts/
│   ├── extract.py                 docx/pdf/xlsx → 文本 + 表格 + 内嵌图片
│   └── build_outputs.py           review.json → 四份交付物
└── assets/
    └── example-review.json        大余县旅投 4800 万元完整实例（可直接跑）
```

## 怎么用

```bash
# 1. 抽取材料（会提示内嵌图片张数 —— 额度测算表常藏在图片里）
python3 scripts/extract.py 授信报告.docx 审计报告.pdf -o _work/

# 2. 按 references/02 逐条点检、按 references/03·04 复算，把结果填进 review.json

# 3. 生成四份交付物
python3 scripts/build_outputs.py review.json -o 输出目录/
```

先跑一遍实例看效果：

```bash
python3 scripts/build_outputs.py assets/example-review.json -o /tmp/demo
```

## 四份交付物

| 文件 | 用途 |
|---|---|
| `XXX-审查报告.docx` | 八段式正式报告 + 关键复算过程附录，可直接上会 |
| `XXX-审查点检表.xlsx` | 六大类逐条留痕，结论着色 + 类别汇总 + 穿透抽查 + 文本一致性 |
| `XXX-补充资料清单.md` | 「不符合」「待补」自动汇总，按上会前／放款前排序，直接发业务团队 |
| `XXX-额度测算底稿.xlsx` | 营运资金缺口法与担保能力**写成活的 Excel 公式**，上会现场可改参数重算 |

## 设计取向

- **形式为主 + 关键实质复算**：点检过流程与准入，只对额度、担保能力、财务勾稽三项独立复算。
- **国企盖章推定形式真实**，不下"造假"结论；但"真实"≠"合理"，逻辑不通的照列并要求书面说明。
- **反套路化**：禁用空话表、每案 2–3 项穿透抽查、至少 1 项清单外发现、对"完美报告"反向提高警惕。
- **算式必须留痕**：任何结论性数字都要能被贷审会成员当场复算。

## 实例验证到什么程度

大余县旅投 4800 万元案例跑完：点检 68 项（不符合 26、待补 21），额度复算 7381.72 万元
与业务团队测算差异 -0.004 万元。该测算表原本以图片嵌在授信报告里、纯文本抽取为空白，
还原后才暴露出三项藏在图里的参数假设 —— 这正是 `extract.py` 提示读图、
`07-穿透抽查池 P502` 要求还原图片型表格的原因。
