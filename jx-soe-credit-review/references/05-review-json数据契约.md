# review.json 数据契约

`scripts/build_outputs.py` 的唯一输入。四份交付物全部由它生成。
未填的可选字段可整块省略，脚本会跳过对应内容。

数值单位统一 **万元**（除非字段名另有说明）；比率用百分数数值（48.63 表示 48.63%）。

---

## 顶层结构

```jsonc
{
  "meta":        { ... },   // 必填
  "报告":        { ... },   // 必填 —— 审查报告 .docx
  "点检表":      [ ... ],   // 必填 —— 点检表 .xlsx
  "补充资料清单": [ ... ],   // 可选 —— 省略时由"点检表"中不符合/待补项自动生成
  "额度测算":    { ... },   // 可选 —— 额度测算底稿 .xlsx
  "担保能力":    { ... },   // 可选
  "财务勾稽":    { ... },   // 可选
  "文本一致性":  [ ... ],   // 可选
  "穿透抽查":    [ ... ]    // 可选（但反套路化要求每案至少 2 项）
}
```

## 报告（→ 审查报告 .docx）

```jsonc
"报告": {
  "标题":     "大余县旅游投资发展有限公司综合授信4800万元的审查报告",
  "履职声明": "本人在此郑重声明，此报告是基于业务部门的调查报告以及其他外部信息进行独立、客观、审慎的论证而成。……",
  "抬头": [
    "申报部门：营业部业务一团队",
    "申请人：大余县旅游投资发展有限公司",
    "申请授信内容：……",
    "主办客户经理：周亚平；调查主责任人：李西平；经营管理主责任人：李西平。"
  ],
  "章节": [
    {
      "标题": "一、借款人与我行合作情况",
      "段落": ["……", "……"]
    },
    {
      "标题": "二、借款人基本情况",
      "子节": [
        { "标题": "（一）基本概况",   "段落": ["……"] },
        { "标题": "（二）生产经营情况",
          "子节": [
            { "标题": "1、当地经济发展状况", "段落": ["……"] },
            { "标题": "2、企业经营情况",     "段落": ["……"] }
          ]
        }
      ]
    }
    // …… 三、财务情况 / 四、征信情况 / 五、担保情况 / 六、授信额度、用途 / 七、风险分析 / 八、审查意见
  ],
  "结尾": "妥否，请审议。"
}
```

- `章节` / `子节` 可无限层嵌套；每层用 `标题` + `段落`（字符串数组）+ 可选 `子节`。
- 需要表格时，在该层加 `"表格": {"表头": [...], "数据": [[...], ...], "标题": "可选"}`。
- **一级标题固定为八段，不增删。**

## 点检表（→ 点检表 .xlsx）

```jsonc
"点检表": [
  {
    "编号":     "A01",
    "类别":     "A 流程与要件合规",
    "点检项":   "报告要素齐备",
    "结论":     "符合",              // 符合 / 不符合 / 待补 / 不适用
    "证据出处": "授信报告 八、调查结论",
    "说明":     ""                   // 不符合、待补、不适用时必填
  }
]
```

脚本会按结论着色：符合=绿、不符合=红、待补=黄、不适用=灰，并生成"类别汇总"页。

## 补充资料清单（→ .md）

省略此字段时，脚本自动把点检表中所有 `不符合` / `待补` 项转成清单。
需要手工增补时：

```jsonc
"补充资料清单": [
  {
    "事项":       "建材采购合同或框架协议",
    "对应点检项": "D01、D02",
    "用途说明":   "验证贸易背景真实性，确定受托支付对象与额度上限",
    "紧急度":     "上会前"           // 上会前 / 放款前 / 放款后
  }
]
```
