# 交付前自检表

出具前逐条自检。任一项不过，返回对应阶段重做，**不得带病交付**。

## 一、完整性

- [ ] 八段式一级标题齐全且顺序正确，无增删
- [ ] 履职声明在开头，`妥否，请审议。` + `审查员：` 在结尾
- [ ] 抬头四要素齐全：申报部门 / 申请人 / 申请授信内容 / 三名责任人
- [ ] 四份交付物全部生成：审查报告.docx、点检表.xlsx、补充资料清单.md、额度测算底稿.xlsx
- [ ] 点检表 A–F 六类**全部有条目**，无整类空缺

## 二、判定质量

- [ ] 点检表每条结论只用了 `符合`/`不符合`/`待补`/`不适用`，无"基本符合"类模糊表述
- [ ] 每条"符合"都有具体证据出处（章节名/表名），无空白
- [ ] 每条"不符合""待补""不适用"都有说明，且说明写清了**要业务团队补什么**
- [ ] 所有"不符合""待补"项都已进《补充资料清单》，条数对得上

## 三、复算留痕

- [ ] 额度做了独立复算，报告中写出**算式**而非只给结果
- [ ] 复算值与报告值的差异及差异率已列示；差异 > 10% 已判不符合
- [ ] 担保能力复算写明了**净资产口径**（母公司/合并/归母）与**基准日**
- [ ] 担保能力中已担保金额是"责任金额"还是"余额"已注明
- [ ] 财务勾稽 K01–K10 已跑，超阈值项已写入报告
- [ ] 报告中每个结论性数字都能被贷审会成员当场复算

## 四、准入

- [ ] 8 条硬红线逐条判过，无遗漏
- [ ] 单一客户/集团限额按**授信总额**卡，不是按"本次新增"
- [ ] 集团限额已按同一实际控制人穿透合并计算
- [ ] 内部评级等级 + **有效期**均已核
- [ ] 软红线偏离项（尤其"非母公司担保"）已单列成段说明理由
- [ ] 有硬红线不符时，审查结论**不是**"拟同意"

## 五、贸易背景与受托支付（会议重点）

- [ ] 已核是否提供采购订单/合同；未提供的判为**不符合**而非"待补"
- [ ] 受托支付对象是否为**上游供应商**已明确判定
- [ ] "放款后 N 日内提交等额发票"已写入授信后管理要求
- [ ] 续授信已回溯上笔受托支付对象与发票收齐情况
- [ ] 委托代建模式下，建材采购主体是否为借款人已穿透

## 六、反套路化

- [ ] 全文无孤立空话：经营稳定 / 风险可控 / 总体良好 / 具备一定担保能力 / 收入稳定增长 / 还款来源有保障 / 信用记录良好 / 前景较好 / 管理规范 —— 每处都紧跟了数据与出处
- [ ] 风险分析 ≥ 3 条，且**全部为本案特有**，每条含：数据 + 出处 + 影响路径 + 缓释措施
- [ ] 至少 2 项穿透抽查已执行并写入报告
- [ ] 至少 1 项清单外的个案发现
- [ ] 授信后管理要求中，≥1 条由本次检出问题反推而来，与检出项一一对应
- [ ] 若各项指标恰好卡阈值内侧，已在报告中明确写出该观察

## 七、定价

- [ ] 本次利率 / 原利率 / 定价指引下限 三者已列示
- [ ] 降价 ≥ 50BP 的已附综合收益测算或明确"建议维持原价 / 以存款结算为降价前提"

## 八、文本

- [ ] 金额单位全文统一，保留两位小数
- [ ] 同一指标在报告各处数值一致（担保人名称、评级、还款计划、金额、期限、利率）
- [ ] 无 emoji、无第一人称"我认为"、无口语化表述
- [ ] 客户名称、担保人名称全称准确，与营业执照一致
